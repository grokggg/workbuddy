## 三、子步骤 3: 配合阶段

**输入**: AI 操作步骤 → **输出**: 用户执行反馈
**原理**: 人机协作(AI 出方案 → 用户执行 → 反馈 → AI 调整)

```
1. AI 定位校验点(步 1) + 给 patch 方案(步 4)
2. 用户执行: python3 five_step_e2e.py <目标> --patch <off> <new> <old>
3. 反馈: 输出验证结果(步 5)
4. AI 调整: 失败则换 patch 模式(je→jmp / jne→nop / call→nop)
```

## 四、子步骤 4: 修改阶段(完整性优先)

**输入**: 校验点(偏移+字节) → **输出**: patch 后二进制
**原理**: 字节替换 + **完整性必须先处理**

**为什么完整性优先**:
```
场景 A(错误顺序): 只 patch 卡密(je→jmp @0xcd)
  → 'x' → BAD rc=2   ← 完整性校验先炸!
场景 B(正确顺序): 先完整性(je→jmp @0x94) + 卡密(je→jmp @0xcd)
  → 'x' → OK rc=0   ✅
```
改字节 → 完整性校验(求和/校验和)检测到变化 → 拒绝。所以**先让完整性检查失效, 再改校验点**。

实测(auth-license):
```
--patch 0x8b eb 74   # 0x8b: je(0x74) → jmp(0xeb)
原始 rc=1 NO → patch后 rc=0 OK
```

## 五、子步骤 5: 验证阶段

**输入**: patch 后二进制 → **输出**: 验证日志
**原理**: 原始失败 + patch 成功对比

```bash
# 原始(应失败)
./auth-license x; echo $?        # NO, rc=1
# patch 后(应成功)
./auth-license-patched x; echo $? # OK, rc=0
```

判据: `orig_rc != 0 and patched_rc == 0` = 破解成功
