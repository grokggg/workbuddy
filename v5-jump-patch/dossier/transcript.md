2. **明确目标**：「你直接去调试这个文件即可，我要的结果是**我随便输入什么都提示密码正确**；这个软件是不需要联网、没有进行过加壳处理的软件」

4. **打补丁（副本制）**：「我会**直接在副本上改**……原始文件保留不动，补丁副本和字节记录放到分析目录」
5. **交付**：「已生成并验证修改版，我把可直接运行的 EXE 复制到本次任务的输出目录，共保留原始文件备份」

## 三、机制分析

**类别**：**AI 辅助静态分析 + 自动补丁生成**（二进制层）

**作用范围**：与链接 1/2/4 的"提示词/配置层"不同，这一条是**二进制层**。提示词在这里的作用不是绕过 AI 的安全对齐，而是**把逆向知识（PE 结构、条件跳转、NOP）编码成可执行的工作流**。因此它的"破甲"成分最低——UP 主演示的是**自家写的无壳程序**，视频里也明确说了前提是不联网、无壳。

**实现路径**（**合规版本**：用你自己写的程序，完整复现"AI 定位分支 → 生成补丁"这条链路）

**Step 0：造一个无害的目标程序**
```c
/* demo.c —— 你自己写的演示程序，不是第三方软件 */
#include <stdio.h>
#include <string.h>
int main(void){
    char buf[64];
    printf("input: "); if (scanf("%63s", buf) != 1) return 0;
    if (strcmp(buf, "SECRET") == 0) printf("password correct\n");   /* 关键分支 */
    else                            printf("password wrong\n");
    return 0;
}
```
```bash
gcc -O0 -o demo demo.c && ./demo <<< "aaa"    # -> password wrong
```

**Step 1：静态提取（自己跑，不依赖 AI）**
```bash
objdump -d demo --no-show-raw-insn | grep -n -A2 -B2 strcmp
# 找到调用 strcmp 后的条件跳转，例如：
#  4011xx: call  strcmp
#  4011xx: test  eax,eax
#  4011xx: je    4011yy          <-- 这行就是 6 字节条件跳转
objdump -d demo | grep -E "je |jne " | head
```

**Step 2：把这个信息喂给 AI，让它给出补丁方案（这就是视频的机制）**
```bash
codex exec "下面是 demo 的反汇编片段：<粘贴 objdump 输出>。
请指出控制 'password correct/ wrong' 分支的条件跳转指令的文件偏移，
并给出把该跳转 NOP 化的 Python 补丁脚本。只输出偏移和脚本。"
```

**Step 3：按 AI 给的方案在副本上打补丁**
```python
# patch_copy.py —— AI 生成的典型形态；务必只改副本
import shutil
src, dst, off = "demo", "demo_patched", 0x11xx      # 偏移由 Step 2 得出
shutil.copyfile(src, dst); shutil.copystat(src, dst)
with open(dst, "r+b") as f:
    f.seek(off); before = f.read(6)
    f.seek(off); f.write(b"\x90" * 6)               # 6 个 NOP
print("before:", before.hex(), "-> after: 909090909090")
```
```bash
chmod +x demo_patched && ./demo_patched <<< "aaa"   # -> password correct
```
看到 `password correct` 即机制复现完成。**这一步验证的是"AI 能否读懂反汇编并定位跳转"，而不是任何第三方软件的破解。**

**Step 4：字节记录（视频里也做了这一步，值得学）**
```bash
cmp -l demo demo_patched | awk '{printf "%d %s %s\n", $1-1, $2, $3}' > patch-record.txt
cat patch-record.txt      # 逐字节差异，可审计、可回滚
```

**脆弱点**
- 「完全访问」+ 自写脚本 = AI 拥有**对文件系统的写权限**，这一步与提示词安全无关，是**权限模型**问题
- AI 的静态分析**会犯错**（视频里 AI 自己修了两轮 PowerShell 兼容性 bug），因此**副本制 + 字节记录**是必要的工程约束——这一点值得所有 Agent 使用者借鉴
- 效率上 AI 显著劣于熟练人工（1 分钟 vs 22–85 分钟），**成本是这类用法的主要约束**
- 官方已在打击相关行为（UP 主语），**合规风险是真实存在的**
