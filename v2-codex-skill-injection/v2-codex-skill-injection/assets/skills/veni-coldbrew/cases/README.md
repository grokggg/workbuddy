# 案例库

## 用途

记录每次"激活 → 自读 → 执行"的实际结果，用来判断 skill 是否稳定生效。

## 为什么默认不回写

视频（BV13nTj6JEWT）里提到的做法是让 skill 随使用自动积累案例。
本复现**默认关闭**自动回写，理由：

1. 案例无限增长会拖慢每次加载 —— skill 正文是**每次命中都要读进上下文**的，
   案例写进正文 = 每次都付这份 token 成本
2. 几个月后大部分案例变成噪音，反而干扰模型的触发判断
3. 案例质量没人把关，会让 skill 的行为随时间漂移

要积累就**人工挑选**后进 `references/`，不进正文。正文保持短。

## 记录格式

```
## YYYY-MM-DD  <一句话场景>

- 输入：
- 是否激活：是 / 否
- 探针 token 是否报出：是 / 否
- 实际行为：
- 备注：
```

## 需要重点记的失败案例

- 激活词**没触发**（换措辞再试，记下哪种措辞能触发）
- 触发了但**报不出 token**（多半是落盘路径问题）
- 触发了但**行为越界**（说明边界段写得不够硬，要改正文第五节）
